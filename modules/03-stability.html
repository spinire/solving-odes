When Euler goes wrong: stability

A smaller step gives a smaller error. But a step that is too large does not just give a larger error: the computed solution can swing wildly and explode, even when the true solution calmly settles down.

Why you'd care 2 min

In Module 2, Euler's method cooled a cup of coffee, $y' = -0.1\,(y - 20)$, $y(0) = 90$, and the error shrank in proportion to the step. Suppose you only care about the temperature after 100 minutes, so you try to save work with a step of $k = 25$ minutes: just four steps.

The true temperature after 100 minutes is $20.003^\circ$C: the coffee has reached room temperature. Euler's method instead says the coffee freezes far below zero, then boils, then freezes harder. The answer is not a little inaccurate. It is nonsense, and it gets worse with every step. This module explains exactly when this happens and what to do about it.

Lesson 1: The test problem 9 min

To see what went wrong, strip the problem down to its simplest form. The coffee cares only about how far it is from room temperature, so call that distance $u = y - 20$. Then $u' = y' = -0.1\,u$: the distance shrinks at a rate proportional to itself. Near an asymptotically stable steady state (Module 1), many equations behave like this, so numerical methods are checked on one simple problem, called the test problem:

$$y' = -r\, y, \qquad y(0) = 1, \qquad r > 0 .$$

The constant $r$ is a positive number that says how fast the process is: for the coffee, $r = 0.1$ per minute. The true solution, $y(t) = e^{-rt}$, decays smoothly to zero. A good method should do the same.

What Euler's method does to it

Euler's step for the test problem is $y_{j+1} = y_j + k \times (-r\, y_j)$. Collect the $y_j$:

$$y_{j+1} = (1 - rk)\, y_j .$$

Each step multiplies the value by the same number, $\kappa = 1 - rk$, called the amplification factor ($\kappa$ is the Greek letter kappa). Starting from $y_0 = 1$, after $j$ steps $y_j = \kappa^{j}$. So everything depends on $\kappa$:

The coffee with $k = 25$ has $rk = 0.1 \times 25 = 2.5$, so $\kappa = -1.5$: every step flips the sign of $u = y - 20$ and makes it 1.5 times larger. That is exactly the table in the opening.

Euler's method is stable for the test problem when $|\kappa| < 1$, so the computed values decay as the true ones do. Since $\kappa = 1 - rk$,

$$-1 < 1 - rk < 1 \quad\Longleftrightarrow\quad 0 < rk < 2$$
$$\Longleftrightarrow\quad k < \frac{2}{r} .$$

The right-hand inequality, $1 - rk < 1$, holds for every positive step. The left-hand one, $-1 < 1 - rk$, is the real condition: it says $rk < 2$.

For the coffee, $2/r = 2/0.1 = 20$ minutes. Any step under 20 minutes is stable; any step over it blows up.

Stability judged this way, by whether the method's values go to zero on the test problem, is called A-stability. A method that is A-stable only when the step is small enough, as Euler's method is, is called conditionally A-stable.

  3. Set $k = 0.5$. What happens after the first step, and why?

    Answer

    $\kappa = 1 - 2 \times 0.5 = 0$, so $y_1 = 0$ and every later value is 0. One step lands exactly on the resting state. The true solution only gets there gradually, so this is stable but not accurate.

Notice what stability does and does not promise. A stable method's values decay when the true solution decays, but they can still be far from it, as in questions 1 and 3. Accuracy is about small errors; stability is about not blowing up. You need both.

Quick check

Lesson 2: Fast and slow: stiff problems 7 min

For the coffee, the stability limit of 20 minutes is no hardship: you would never want a step that large for accuracy anyway. Trouble comes when a problem mixes a fast process with a slow one.

Picture a thermometer in a room whose temperature drifts slowly up and down over the day. The thermometer reacts quickly: it closes most of the gap to the room temperature within a couple of minutes. With time $t$ in hours, its reading $y$ obeys

$$y' = -50\,\big(y - \cos t\big), \qquad y(0) = 0 ,$$

where $\cos t$ is the slowly changing room temperature (on some scale). The reading is pulled toward $\cos t$ at a rate proportional to the gap, with $r = 50$ per hour. After a fast start, the reading simply follows the slow curve $\cos t$.

To follow a curve as gentle as $\cos t$ accurately, a step of $k = 0.1$ hours would be plenty. But the gap between the reading and the room temperature behaves essentially like the test problem with $r = 50$ (plus a small, slowly changing push from the room), so Euler's method is stable only when

$$k < \frac{2}{50} = 0.04 \text{ hours}.$$

And that limit never goes away, even long after the fast start is over and the solution is as smooth as can be. Try it:

A problem like this, where a fast process that has long since settled still forces a tiny step, is called stiff. Stiff problems are common, for example in chemistry, where some reactions take microseconds and others hours. For a stiff problem, the number of Euler steps is set by stability, not by the accuracy you want.

Lesson 3: What to do about it 4 min

Option 1: respect the limit. If you know roughly how fast the fastest process in your problem is, its $r$, keep the step below $2/r$. For problems that are not stiff, this costs nothing.

Option 2: change the method. Euler's method uses the slope at the start of the step. Backward Euler uses the slope at the end:

$$y_{j+1} = y_j + k\, f(t_{j+1}, y_{j+1}) .$$

For the test problem, $f(t, y) = -ry$, so this reads $y_{j+1} = y_j - rk\, y_{j+1}$. Move the $y_{j+1}$ term to the left, $(1 + rk)\, y_{j+1} = y_j$, and divide:

$$y_{j+1} = \frac{1}{1 + rk}\, y_j .$$

Now the amplification factor $1/(1 + rk)$ is between 0 and 1 for every step $k > 0$: the values always decay, however large the step. Backward Euler never blows up on the test problem: it is A-stable, with no condition on the step.

The catch: $y_{j+1}$ appears on both sides of the formula, so each step means solving an equation for $y_{j+1}$, not just evaluating a formula. A method like this is called implicit; Euler's method, which gives $y_{j+1}$ directly, is explicit. For a stiff problem, the extra work per step is well worth it, because far fewer steps are needed. Solvers for stiff problems use a family of implicit methods called BDF (backward difference formula) methods, of which backward Euler is the simplest; scientific software offers them as special options for stiff problems (Module 5).

Takeaways

  • The test problem $y' = -ry$ ($r > 0$) has a solution that decays to zero. A method should reproduce that.
  • On it, Euler's method multiplies by $\kappa = 1 - rk$ every step. It is stable when $|\kappa| < 1$, that is, when $k < 2/r$: Euler's method is conditionally A-stable. Beyond that limit, the values flip sign and grow.
  • Stable is not the same as accurate: a stable method can still be far off. Accuracy needs a small error; stability only rules out blowing up.
  • A stiff problem has a fast process that forces a tiny step through stability, even when the solution is smooth.
  • Backward Euler, $y_{j+1} = y_j + k\, f(t_{j+1}, y_{j+1})$, decays for every step size on the test problem (it is A-stable), at the cost of solving an equation each step: it is implicit.
